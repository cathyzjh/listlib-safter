# 高级数据类型（列表 / 字典）· Mind+ 用户库安全版

给 **Mind+ V1.8 上传模式 + Arduino C + 行空板 K10** 补上一组「对标 Python 高级数据类型」的积木。

> v1.2.0：修复自身切片丢数据、字典初始化残留和名称表达式处理；增加容量限制、可检查的分配失败、错误查询和释放容器积木。基于原项目的 MIT 许可修改，保留原始许可。

官方 K10 上传扩展只有固定长度数组，没有 `append / pop / 排序 / 切片 / 字典`。这个库用「名字 → 容器」的运行时注册表，在 Arduino C++ 中提供接近 Python 的列表、字典操作；并非完全兼容 Python：

- 列表名可以随时新建，**支持中文名**（`数据`、`温度历史` 都行）
- 列表在容量限制内自动增长，不用提前写死长度
- 索引从 0 开始，**支持负索引**（`-1` 是最后一项），和 Python 一致
- 越界读取返回 0 / 空文本，同时记录错误码；可在积木中查询
- 列表、字典必须先创建或初始化；追加、插入、设置不会隐式创建拼错名称的容器

## 一、安装

### 方式 A：直接导入成品库（推荐）

1. 打开 Mind+，进入**上传模式**，选择主控 **行空板 K10**
2. 点左下角「扩展」→ 顶部「用户库」→「导入用户库」
3. 选择 `listlib-safter-V1.2.0.mpext`
4. 回到扩展页，能看到「高级数据类型（列表/字典）」卡片，积木区多出 `listlib_safter` 分类

### 方式 B：导入源码目录调试

把 `config.json` 直接拖入「导入用户库」对话框（选择 config.json 文件），会进入**调试模式**，改代码后点积木区右上角的刷新按钮即可生效。

## 三、批量初始化怎么用

三个积木都支持「一次填一串」，创建和赋值一步完成（等价 `lst = [1,2,3]`）：

| 积木 | 输入示例 | 结果 |
| --- | --- | --- |
| 把数字列表 `lst` 初始化为 `...` | `1,2,3,4` 或 `25.5, 24.1 ,23.8` | 4 个元素，空格和多余的逗号会自动忽略 |
| 把数字列表 `lst` 初始化为 `...`，分隔符 ` ` | `10 20 30` | 空格分隔也能拆，适合粘贴传感器数据 |
| 把文本列表 `words` 初始化为 `...` | `红,绿,蓝` | 3 个文本元素 |
| 把文本列表 `words` 初始化为 `...`，分隔符 `|` | `a|b|c` | 文本本身带逗号时换个分隔符 |
| 把字典 `d` 初始化为 `...` | `temp:25,hum:60` | 2 个键，值分别是 25 和 60 |

规则：
- 每个元素前后的空格会被自动去掉
- 结尾多打的逗号不会生成空元素，空项会被跳过
- 非法数字、没有冒号或空值（如 `noVal:`）会使整个初始化失败，错误码为 6，原内容保持不变；不再把错误输入静默当成 0
- 不接受 NaN、Infinity 或超出 double 表示范围的数字；空元素仍会跳过
- 初始化是**覆盖**：原来列表里的内容会被清空

## 四、K10 示例：温湿度历史（自动淘汰旧数据）

效果：每次读温湿度存进列表，列表最多保留 10 条，超了就删最早的一条 —— 这就是 Python 里
`history.append(t); if len(history) > 10: history.pop(0)` 的等价写法。

积木顺序：

1. `创建数字列表` 名字填 `温度历史`
2. `创建数字列表` 名字填 `湿度历史`
3. 放进「循环执行」：
   - `向数字列表 [温度历史] 追加 [读取 温度（摄氏度℃）]`
   - `向数字列表 [湿度历史] 追加 [读取 湿度（%RH）]`
   - `如果 [列表 温度历史 的长度] > 10 那么` → `删除列表 [温度历史] 第 [0] 项`
   - 同样的判断给 `湿度历史`
   - `用分隔符 [,] 拼接数字列表 [温度历史]` → 用「缓存显示文字」显示到屏幕第 1 行
   - `等待 1 秒`

生成的 C 代码大致是：

```cpp
void loop() {
    ListLib::addNum("温度历史", temp_humi.read_temp());
    ListLib::addNum("湿度历史", temp_humi.read_hum());
    if (ListLib::size("温度历史") > 10) { ListLib::removeAt("温度历史", 0); }
    if (ListLib::size("湿度历史") > 10) { ListLib::removeAt("湿度历史", 0); }
    display.drawText(ListLib::dumpNum("温度历史", ","), 0, 1, ...);
    delay(1000);
}
```

## 六、常见问题

**1. 导入后库显示「不可用」**
`config.json` 里的 `board` 写的是 `esp32s3bit`（K10 在 V1.x 用户库体系里的主控标识）。
若显示不可用，用记事本打开 `config.json`，把 `"board": ["esp32s3bit"]` 临时改成
`"board": ["esp32s3bit", "esp32", "mpython"]` 再重新导入；仍不行就把该行换成你在
Mind+ 安装目录下 K10 主控库 `config.json` 里看到的 `board` 值。

**2. 报 `'ListLib' has not been declared`**
说明 `arduinoC/libraries/listlib/listlib.h` 没被打包进去。确认该文件存在，且目录层级是
`arduinoC/libraries/listlib/listlib.h`（必须多一层子目录，不能直接放 libraries 下）。

**3. 取到 0 或空文本**
索引越界，或列表名拼错（名字必须和「创建」积木里写的完全一致，中文也算）。
`-1` 表示最后一项，`-2` 倒数第二项，和 Python 一样。

**4. 能不能存文本进数字列表？**
不能混用。数字列表只收数字，文本列表只收文本，这是 C 和 Python 最大的区别 ——
Python 的 `list` 可以混装，C 必须定类型。要混装就拆成两个列表。

**5. 内存占用**
安全版有硬性容量限制，超限会拒绝操作并记录错误码。限制不能保证整块板子的可用内存，因此仍检查分配失败。长期采集建议像示例那样淘汰旧数据，使用后清空或删除容器。

## 八、安全版的容量、错误和兼容性

| 限制 | 默认上限 |
| --- | --- |
| 列表和字典合计数量 | 16 |
| 每个列表的元素 / 每个字典的键 | 256 |
| 容器名称 | 1–64 UTF-8 字节 |
| 单项文本 / 字典键 | 256 UTF-8 字节 |
| 一次初始化输入 | 4096 UTF-8 字节 |
| 拼接结果 | 4096 UTF-8 字节 |
| 所有容器的逻辑数据预算 | 32768 字节 |

逻辑数据预算包括数字、字符串对象和文本字节，不等于总堆占用；还存在容器名称、数组预留容量、分配器开销和操作期间的临时副本。容量是保守的默认值，不假设 PSRAM 一定可用。单项文本长度按字节计算，中文通常每字占多个字节。库内不使用抛异常的 STL 动态容器，数组使用 `new(std::nothrow)`，字符串复制、拼接检查分配结果。外部调用者在调用前创建参数所需的内存不由库控制。

所有操作共享一个“上次错误”状态；成功的操作会重置为 0。**必须紧接着查询**，不要先调用另一个容器积木。查询错误码、错误说明本身不重置状态。普通包含查询返回 false、查找位置返回 -1，表示没有匹配项时不算错误；直接读取不存在的字典键会报错。

| 错误码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 1 | 容器不存在 |
| 2 | 列表类型不匹配 |
| 3 | 索引越界 |
| 4 | 超出容量限制 |
| 5 | 内存分配失败 |
| 6 | 名称或数字等输入不合法 |
| 7 | 字典键不存在 |
| 8 | 对空列表求最大值、最小值、平均值 |

新增积木：删除整个列表、删除整个字典、查询错误码、查询错误说明、清除错误状态。Arduino C++ 还可调用 `ListLib::resetAll()` 释放全部容器。

“清空列表”释放元素及数组占用，但保留名称和类型；“删除整个列表”连同注册项一起释放。字典同理。重新创建同名列表或字典会得到空容器。字典和列表的命名空间独立，字典键仍按文本顺序输出。

索引必须是 32 位有符号范围内的整数；小数、NaN、Infinity 和超大值会报错，不会直接进行不安全的浮点到整数转换。

切片采用左闭右开 `[A, B)`，支持负索引；例如 `0, -1` 不含最后一项。复制整个列表请使用“完整复制”。源与目标同名也安全。初始化、复制、切片失败会保留目标原内容；插入、追加、设置失败不会丢弃原数据。

本版本继续使用原有积木命名与 C++ 操作接口，但修正了以前的隐式创建和无效数字处理。本 fork 使用独立扩展 ID 和积木命名空间 `listlib_safter`；旧项目中的原版积木不会自动迁移，需替换为安全版积木。迁移时，应显式创建容器并检查错误。内部 `store()/dictStore()/find()` 等实现细节已移除，防止绕开限制；这些不属于积木 API。名称输入可直接接变量或文本表达式，生成器保留 Mind+ 生成的表达式和字符串转义，不再手动拆装引号。

仅支持单任务顺序调用；多任务、回调并发调用同一全局存储时，需要调用方自行同步。错误说明为英文短语，低内存下优先查询无需字符串分配的错误码。

## 九、开发检查与打包

在项目根目录执行：

```sh
python3 scripts/check.py
python3 scripts/package.py --output-dir dist
```

检查脚本需要 Python 3、Clang++ 或 G++，以及 Node.js。它运行 C++11 无异常模式的边界和失败注入测试、42 个积木生成器测试，并编译生成的 C++ 片段。Clang 默认启用 AddressSanitizer 和 UndefinedBehaviorSanitizer。桌面测试使用带失败注入的 Arduino String 适配层，不代替 Mind+ 导入、K10 编译和真机压力测试。

打包脚本从 `config.json` 自动读取版本，只包含运行所需文件，并核验包内版本、积木入口、源码及 SHA-256；可重复运行以避免手工发布旧包。发布时上传脚本生成的同版本 `.mpext` 和校验文件。历史上游 Release 不会被本地打包自动改变。
